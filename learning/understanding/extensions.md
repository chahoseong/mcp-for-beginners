## 후속 확인 목표

- working과 실제 결과의 구분·상태 추적 흐름은 테스트 사례에서 확인했다. 이후 구현 수업에서 작업 식별자와 조회 메서드를 연결한다.
- Task 상태·완료와 최종 도구 결과의 의미를 구분한다. 상세 입력 요청·취소·저장·SDK 구현은 이 수업에서 요구하지 않는다.

## 설명 보충과 평가 경계 — 2026-10-06

- MCP Apps 후속 질문에서 iframe 표시를 Host 역할, MCP 통신을 Client 역할로 다시 설명했다. Python의 apps.add_html_resource는 UI Resource 등록, resource_uri는 Tool과 화면의 연결 참조임을 보충했다. 학습자의 독립 답변 평가는 없으며 위 상태·확인 날짜를 올리지 않는다.
- 시간/FAQ·실패 표시·버튼 복구는 안내 구현의 실행 근거이다. 최종 사용 시점 적용 확인과 전체 새 앱 독립 구현은 구분한다.
