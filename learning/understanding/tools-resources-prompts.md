## 후속 확인 목표

- 도구의 이름·입력·출력·활용 흐름 개요 설계는 확인했다. 상세 출력 필드의 설계는 해당 구현 내용을 배우는 시점에 다룬다.
- 실행 결과·종료 코드·요구사항이 주어진 다른 코드 사례에서 무엇을 확인할 수 있으며 어떤 추가 검증이 필요한지 설명하게 한다. 질문 자체에 기능 오류 여부나 종료 코드의 결론을 넣지 않는다.
- 실행 성공의 의미는 보충 설명 이후 재확인하지 않았다. Prompts와 모델 응답 생성의 구분은 Module 01에서 확인했다.

## 확인 방식의 한계 — 2026-10-01 검토

- Resource 읽기·Prompts·날씨 API 필요성은 설명과 가까운 사례의 답변이다. 독립적 전이 능력까지 평가한 것은 아니다.
- 인자 명세, Annotations, 등록 시점, 기본값, self, 서버 시작은 직전 설명의 재현 또는 유도·선택 질문으로 확인했다. 기존 상태는 보존하되 독립 적용의 증거로 해석하지 않는다.
- 후속 설계·코드 읽기에서 핵심 구분을 다른 사례로 재확인하고, 힌트 없이 설명한 근거를 추가한다.

## 평가 변화

- 2026-10-04: greeting 템플릿 실습 후 새 profile://{user_id} 사례에서 읽기 URI·메서드·조회와 내용 읽기 차이를 설명하여 Resource의 발견과 읽기를 이해 확인에서 적용 확인으로 갱신했다. 과거 근거와 확인 방식 한계는 보존한다.
- 2026-10-02: Module 03에서 학습자가 greeting://Mina 읽기의 contents(uri, mimeType=text/plain, text=Hello, Mina!)를 제출했다. Resource의 발견·읽기 기존 이해 확인 상태는 유지하고 안내에 따른 실제 템플릿 읽기 경험을 추가한다. 독립 설계·구현의 근거는 아니다.
- 2026-10-02: Module 03 첫 실습에서 학습자가 Inspector의 Connected와 안내한 add(7, 9) 호출 결과 {"result": 16}을 제출했다. 기존 Python 도구 등록·실행 및 FastMCP 서버 실행의 이해 확인 상태는 보존하며 안내를 따른 연결·호출 경험을 추가한다. 다양한 입력에 대한 정확성이나 독립 구현 능력까지 확인한 것은 아니다.
- 2026-10-02: Module 03에서 List Tools로 Client가 도구 목록과 명세를 얻지만 도구는 아직 실행되지 않았다고 답했다. 목록 조회·실행 구분을 이해 확인으로 기록한다. 직전 설명과 가까운 사례이며 독립 적용이나 실제 호출 성공 근거는 아니다. Python 도구 등록과 실행의 기존 상태는 보존한다.
- 2026-10-02: 첫 설계에서 이름·목적·필수 경로·반환 정보·활용 흐름을 제안했으나 자료형이 없어 부분 이해로 기록했다. 후속 답변에서 filepath: str을 제시했다. 출력 필드의 세부 분해까지 요구한 질문은 원문 연습보다 상세했으므로 철회하고, 제출한 개요 설계를 적용 확인으로 갱신했다. 구현 수준의 명세가 완성됐다는 평가는 아니다.
