## 개념별 최신 상태

| 개념 | 상태 | 답변 근거와 확인 방식 | 마지막 확인일 | 후속 확인 |
| --- | --- | --- | --- | --- |
| 요구사항에 따른 배포 위치 선택 | 이해 확인 | 개인 문서 접근 사례에는 로컬 프로세스, 개발자 컴퓨터 종료 후 팀 공유 사례에는 클라우드를 선택했다. 이유를 묻는 집중 후속 질문에 사용자 컴퓨터 문서 접근과 지속 실행·원격 접속을 설명했다. 실행 위치 비교를 설명한 뒤 주어진 요구사항에 적용한 근거이다. 클라우드가 자동으로 무중단을 보장하지 않고 원격 접근도 허가 사용자로 제한할 수 있음을 평가 시 보충한다. | 2026-10-05 | 로컬 Docker·Render 배포 실행은 확인했다. 독립 운영 설계·고가용성 구현은 미평가이다. |
| Image와 Container | 이해 확인 | Image/Container·Dockerfile build/run을 설명하고 v1 생성·실제 호출을 수행했다. 호스트 코드 수정 후 기존 Container restart만 하는 사례에서 반영되지 않으며 COPY는 이미지 생성 시 실행돼 그 시점 파일을 복사한다고 설명했다. 질문에서 COPY를 판단 근거로 제시한 집중 확인이다. v2 build·교체 안내 후 실제 응답의 deployment-practice-v2 이름과 계산값2.5를 제출했다. | 2026-10-05 | 독립 전체 배포 설계·갱신 실패 진단은 미평가이다. |
| 원격 코드 갱신의 점검 경로 | 이해 확인 | 로컬에만 multiply가 발견되는 새 사례에서 GitHub에 갱신한 스크립트가 업로드됐는지 확인하고 Render 재배포를 제안했다. 점검 경로를 직접 제안했으며 build·배포 성공 로그 확인은 평가 피드백으로 보충한다. | 2026-10-05 | 실제 원격 갱신 실패 재현·복구와 독립 운영 진단은 미평가이다. |

## 최종 실행 근거와 한계

- 2026-10-05: Docker Client/Engine29.8.0·Desktop4.92.0·Linux Engine/amd64를 확인하고 Python3.12-slim·MCP2.2.0의 v1 Image와 Container를 안내에 따라 생성했다. 0.0.0.0:8000 bind·127.0.0.1:8080→8000 publish와 시작 로그·HTTP 정상2.5/0 분모 오류를 확인했다. 두 응답은 HTTP200이고 isError:false/true이다.
- 같은 날 v2 재빌드·v1 stop·새 Container run 뒤 deployment-practice-v2·2.5 응답을 제출했다. v2 Container 목록/ID는 미제출이며, 응답의 갱신 확인과 구분한다.
- Render 선택·GitHub 실습 저장소와 HTTPS 주소 제출 후, 에이전트가 tools/list·add/divide를 확인했고 학습자가 원격 정상2.5/0 분모 오류·HTTP200·isError:false/true를 제출했다. 실제 원격 호출은 완료됐으며 Azure 배포는 미실습이다. 현재 원격 서비스의 가동 상태를 새로 검증한 기록은 아니다.
- 안내된 배포/갱신과 독립 운영 설계를 구분한다. 고가용성·운영 인증·원격 갱신 실패 재현/복구는 미평가, 로컬 자원 정리 실행은 미확인이다. Render 삭제는 요청하지 않았다.
- 단계별 출력·ID·실습 주체는 [실습 근거 보존](../lessons/history/03-implementation-evidence-2026-10-06.md), 배포 선택·교정 경위는 [Deployment 상세](../lessons/history/03-deployment-2026-10-05.md)에 보존했다. 이동으로 이해 상태를 바꾸지 않았다.
