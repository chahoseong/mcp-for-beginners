## 후속 확인 목표

- 감사 기록 질문은 가르치지 않은 권한 검사 절차를 요구하는 것으로 해석될 여지가 있었다. 현재 추가 평가를 멈추며, 이후 기록 설계·검사 절차를 실제로 배울 때 재확인한다.
- 도구 목록 표시와 서버의 실제 접근 통제도 구분해야 한다. 아직 보안 구현 실습은 하지 않았다.

## 확인 방식의 한계 — 2026-10-01 검토

- 인증·인가 분류, 사용자 동의, 입력 검증은 직전 설명과 같은 사례 또는 유도 질문으로 확인했다. 입력 검증 답변에는 이유가 있었지만 독립적인 새 사례 적용을 평가한 것은 아니다.
- 기존 이해 확인을 보존하되 독립 이해의 근거가 제한적임을 함께 해석한다. 보안 개요를 다른 사례에서 설명·진단하게 하여 필요한 구분을 재확인한다.

## 평가 변화

- 2026-10-02: 노트 조회 과부하를 권한·입력 검사만으로 해결할 수 없다고 판단했으나 대응 방법은 제시하지 못해 요청 제한을 부분 이해로 평가했다.
- 2026-10-02: 재설명 후 다른 공유 API 사례에서 사용자별 균등 배분을 제안하여 이해 확인으로 갱신했다. 도움 없이 처음부터 대응을 도출한 것으로 기록하지 않는다.
- 2026-10-02: HTTPS 비공개 노트 유출 사례에서 권한 검사 조사 지점을 제시했다. 통신 보호와 접근 통제를 이해 확인으로 갱신했으나 감사 기록 질문에는 아직 답하지 않았다.
- 2026-10-02: 감사 기록의 후속 질문에서 요청 당시 Client 정보·Resource 권한·검사 프로세스를 제안하여 부분 이해로 갱신했다. 실제 실행·판단의 기록을 뜻하는지는 추가 확인한다.
- 2026-10-02: 학습자가 권한 검사 절차는 배우지 않았다고 지적했다. 위 후속 확인을 중단하고 평가의 한계를 기록했다. 원문의 짧은 Audit Logging 개요보다 상세한 절차를 전제하는 질문은 하지 않는다. 기존 부분 이해는 조사 근거 답변의 제한된 평가이며 이번 범위 지적 때문에 낮춘 것이 아니다.
