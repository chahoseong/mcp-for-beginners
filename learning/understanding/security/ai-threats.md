## 최신 이해

| 개념 | 관련 모듈 | 상태 | 확인 근거 | 마지막 확인일 | 후속 과제 |
| --- | --- | --- | --- | --- | --- |
| Indirect Prompt Injection | 02 | 적용 확인 | 비공개 파일 전송 예시와 다른 리뷰 비교 사례에서, 웹 페이지의 부정적 리뷰 제외 지시가 모델의 참고 자료와 답변을 왜곡하여 사용자 요청에 어긋난다고 설명하고 공격을 정확히 분류했다. 추가 힌트 없이 답했다. | 2026-10-02 | 적용 확인은 이 콘텐츠·답변 왜곡 사례에 한정한다. 공격 차단 구현이나 모든 Server 신뢰 경계까지 확인한 것은 아니다. |
| Tool Poisoning·Rug Pull | 02 | 이해 확인 | 최초 승인 후에도 도구 안전성이 계속 보장된다고 판단하는 것은 잘못이며, 도구 설명이 모델의 Context와 결과 생성에 영향을 주므로 계속 확인해야 한다고 설명했다. | 2026-10-02 | 직전 설명과 유사한 변경 사례의 인과 설명으로 확인했다. '매번 확인'은 지속적인 변경 검증 취지로 해석하며 매 호출 전 전체 검사라는 명세 의무로 기록하지 않는다. 실제 검사 설계·제품 설정은 평가하지 않았다. |

## 이후 확인

- 공격 차단 구현과 제품 설정은 수행하지 않았다. 기존 답변의 적용 범위·도움 여부는 각 행의 한계를 따른다.
