## 확인 방식의 한계 — 2026-10-01 검토

- 인증·인가 분류, 사용자 동의, 입력 검증은 직전 설명과 같은 사례 또는 유도 질문으로 확인했다. 입력 검증 답변에는 이유가 있었지만 독립적인 새 사례 적용을 평가한 것은 아니다.
- 기존 이해 확인을 보존하되 독립 이해의 근거가 제한적임을 함께 해석한다. 보안 개요를 다른 사례에서 설명·진단하게 하여 필요한 구분을 재확인한다.


## 이후 확인

- 2026-10-06 Simple Auth 마무리 보충: OAuth 발견의 시점·목적, 브라우저와 설치형 Client의 요청/응답 분리·콜백, Code와 PKCE 교환을 단계별로 설명했다. OAuth 인가 표준과 OIDC 인증, 다른 grant 개요·Access Token은 JWT 필수가 아님·실습 scope 이름과 의미는 자체 정의임을 보충했다. 학습자가 이해를 보고하고 JWT 필수 여부·scope 정의 주체를 확인하는 질문을 했다. 설명 뒤 자기 보고/확인성 질문이며 독립 적용 평가로 사용하지 않고 기존 상태를 유지한다. 실제 OAuth 구현은 미실습이다.
- 2026-10-05 CORS 보충: 학습자가 허용 대상과 요청 출처를 계속 질문해 웹페이지 서버·브라우저·날씨 API 서버의 순서 그림으로 설명했다. 그림 뒤 이해했다고 보고했으며 자기 보고만으로 위 부분 이해 상태를 올리지 않는다. 기존 HTTPS·CORS·미인증 Python Client 사례를 재개해 보안 역할 구분을 확인한다.
- 감사 기록의 구체적 검사 절차는 아직 가르치지 않아 평가를 중단했다. 실제 구현을 배울 때 관련 범위만 확인한다.
- 도구 목록 표시와 실행 권한의 구분은 보충했으며 독립 답변 평가는 없다.
