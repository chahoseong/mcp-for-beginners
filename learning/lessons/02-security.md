# Module 02 — Security 수업 요약

- 원문: [02-Security/README.md](../../02-Security/README.md)
- 진행 상태: README 개념 학습 완료(2026-10-02). 인증·인가·토큰·최소 권한, AI 공격·방어, Confused Deputy, 상태 탈취, 공급망과 운영 보안·도구 개요를 다뤘다. 제품·배포·Sherpa 실습은 학습자 요청으로 생략했다.
- 목표: MCP의 공격·오용이 생기는 지점을 식별하고, 해당 지점에 필요한 방어 원칙을 연결한다.
- 소개 범위: 인증·인가와 토큰·최소 권한, Prompt Injection·Tool Poisoning, Confused Deputy·상태 탈취, 공급망, 다층 방어·감사·Microsoft 보안 도구.
- 다음 행동: Module 03 시작 요청 시 원문 개요와 Python 경로를 소개한다. 모듈 완료를 모든 개념의 독립 적용·실제 운영 능력 확인으로 해석하지 않는다.
- 학습 순서: 접근 권한·토큰 → AI 입력·도구 메타데이터 공격 → 중계·상태 악용 → 공급망·운영 방어. 관련 짧은 항목은 묶고 원문 개요를 불필요하게 구현 수업으로 확장하지 않는다.
- Python 설치·코드 실행·Azure 배포 또는 Sherpa 실습은 아직 수행하지 않았다.

## 이어갈 확인과 범위

- Module 01의 실행 도구 설계와 노트 조회 사례를 필요한 보충 예시로 연결한다. 예시와 원문을 구분한다.
- 감사 기록 상세 설계·권한 검사 절차는 설명되지 않은 상태이다. 실제로 가르친 범위 안에서만 평가한다.
- 기존 유도 질문의 핵심 개념은 새 사례에서 자연스럽게 재확인한다. 전체 복습을 모듈 진입 조건으로 강제하지 않는다.
- 학습자 요청에 따라 현재 단계에서는 실제 보안 솔루션 설정·배포, Sherpa 워크숍 등 실습을 생략한다. README 개념과 짧은 사고·설계 사례 중심으로 진행한다. 제품의 역할은 개요로만 소개하며 실습 재개는 학습자의 요청이 있을 때 검토한다.

## 원문 주의사항

- 2026-07-28 업데이트와 이전 프로토콜 세션 관리·DCR 설명이 혼재한다. 해당 주제에서 현재 명세·이전 버전·애플리케이션 상태를 구분한다.
- 보안 제품 소개를 모든 공격의 차단 보장으로 해석하지 않는다. 역할과 한계를 개념 수준에서 설명한다.
- 원문의 모든 서비스 계정 MFA 요구는 계정 유형을 구분해야 한다. 사용자 기반 계정과 비대화형 workload identity는 같은 방식으로 MFA를 적용하지 않는다. 마지막 단위에서 공식 근거로 보충한다.
- 구체적 MUST·OAuth 흐름·제품 기능 등은 해당 주제에 도달하면 공식 근거를 확인한다.

- 2026-10-02: 마지막 운영 계획에서 작업 디렉토리·권한 제한, 로그 민감정보 보호, 문서 속 지시 실행 방지를 제안하여 개념 학습을 마무리했다. Authorization 헤더의 토큰·키도 로그에서 제외해야 함은 후속 보충이며 독립 답변 근거로 기록하지 않았다.
- 2026-10-02: 종료 시 보안 기록을 세 주제 문서와 INDEX로 분리하고 기존 평가를 history에 보존했다. 재구성만으로 기존 이해 상태를 변경하지 않았다.

- 2026-10-02: 처음에는 대화창 요약에 파일 쓰기를 추가로 가정했으나, 재설명 후 원본·요약 저장소의 권한과 이유를 구분하여 최소 권한을 이해 확인으로 갱신했다. 도움 이후의 확인으로 기록한다.
- 2026-10-02: Module 02 개요 학습을 시작했다. 원문 범위에 맞춰 주제를 묶었으며 설명만으로 이해 상태를 갱신하지 않았다.
