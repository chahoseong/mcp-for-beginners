## Sampling 단원 검토

- 2026-10-06 README와 현행 Sampling/Deprecated Features 명세를 확인했다. 학습 목표는 개념·설정·실행 예시이며01에서 Host 측 모델에 생성 요청하는 개념을 다뤘다. 기능은2026-07-28부터 deprecated이고 신규 도입을 권하지 않으며 직접 LLM API로 이전하도록 안내한다. 삭제 예정일을 확정 날짜로 표현하지 않는다.
- 제안: 개념과 Client LLM 활용/Server 직접 LLM 호출의 차이는 짧게 보충하고 구형 ctx.session.create_message·초기화 기반 설정·상품 설명 과제는 선택 보류한다. 실제 레거시 유지보수 요구가 있으면 별도 버전/Host 호환 조건을 확인한다. 학습자의 보류 선택·실행·독립 이해 근거는 아직 없다.
- 원문 보완: 현행 호환 절차는 요청별 capability 메타데이터와 InputRequiredResult/inputRequests·재요청 inputResponses를 사용하므로 구형 standalone 역방향 요청 예제를 현행 방식으로 설명하지 않는다. 반환 id에 post.title을 넣는 예제 오류도 확인했다. 원문 자체는 수정하지 않았다.
- 수업 계획 작성(2026-10-06): 사용자 요청에 따라 개념/설계 비교 중심으로 구성했다. 그림으로 기존 Sampling의 Server 생성 요청·Client 모델 제어→현행 deprecated 상태/호환 절차 개요→Server 직접 API 호출과 모델·키·비용·데이터 전송 책임 비교→원문 상품 설명 시나리오를 코드 없는 흐름 설계로 적용한다. 원문 설정/실행 목표는 개요만 다루고 실제 충족했다고 기록하지 않는다. 레거시 별도 버전 실습 또는 Server NIM 직접 호출 구현은 선택 확장으로 남긴다. 승인·실행·독립 이해 평가 근거는 아직 없다.
- 시작(2026-10-06): 계획을 승인했다. 첫 구간은 개념 수준의 요청/생성 결과/최종 Tool 결과를 그림으로 설명하고 이전 LLM Client와 비교한다. 그림의 화살표를 구형 역방향 JSON-RPC wire 절차로 일반화하지 않는다. 다른 가격 조회·구매 조언 사례의 판단 근거는 답변 대기 중이다. 새 구현 실행은 없다.
- 개념 확인(2026-10-06): 가격 조회 뒤 Host가 조언을 생성하는 새 사례는 Sampling이 아니고 Server의 작업 중 생성 요청 과정이 없다고 설명했다. Server의 요청 주체를 근거로 개념 구분을 확인했으며 최신 평가는 Client Primitives 기록에 둔다. 이후 지원 조건·설정 의미·직접 API 호출의 책임 비교를 설명한다.

## 마무리 근거

- 지원 선언은 실제 기능 구현이 아님·modelPreferences는 선호·maxTokens는 생성 응답의 최대 토큰 수임을 설명했다. 현행 요청별 capability/구형 초기화 설정 차이는 개요이며 실제 설정 실습은 없다.
- Server의 직접 NIM 호출 그림과 모델 연결/키·데이터·실패·비용 책임을 비교했다. NIM API 자격과 사용자의 MCP 접근 토큰은 다른 역할임을 보충했다.
- 학습자는 상품 설명 설계에서 Client→Server create_product(title,keywords), Server→NIM 생성 요청, Server→Client title/description 반환을 작성했고 NIM 설정/키는 Server가 관리한다고 답했다. NIM→Server 응답 단계는 생략되어 교사가 보충했다. 안내된 흐름을 다른 업무에 활용한 답변이며 실제 구현·독립 전체 설계는 아니다.
- 개념/설계 비교 수업을 완료했으며 레거시 설정/실행과 새로운 Server NIM 구현은 선택 확장으로 남겼다. 미실습인 원문 학습 목표까지 완료했다고 기록하지 않는다.
- 완료 시 누적 검토/계획을 이 파일에 보존하고 모듈은 재개 요약으로 줄였다. 이동 자체로 평가는 변경하지 않았다.
