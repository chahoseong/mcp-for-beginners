## 후속 확인 목표

- 노트 요약 서비스 운영 계획에서 우선 수정할 두 항목과 이유·대안을 확인한다. 보안 도구 설치만으로 방어가 완성된다고 판단하지 않는지 살핀다.
- 감사 기록 질문은 가르치지 않은 권한 검사 절차를 요구하는 것으로 해석될 여지가 있었다. 현재 추가 평가를 멈추며, 이후 기록 설계·검사 절차를 실제로 배울 때 재확인한다.
- 도구 목록 표시와 서버의 실제 접근 통제도 구분해야 한다. 아직 보안 구현 실습은 하지 않았다.

## 확인 방식의 한계 — 2026-10-01 검토

- 인증·인가 분류, 사용자 동의, 입력 검증은 직전 설명과 같은 사례 또는 유도 질문으로 확인했다. 입력 검증 답변에는 이유가 있었지만 독립적인 새 사례 적용을 평가한 것은 아니다.
- 기존 이해 확인을 보존하되 독립 이해의 근거가 제한적임을 함께 해석한다. 보안 개요를 다른 사례에서 설명·진단하게 하여 필요한 구분을 재확인한다.

## 평가 변화

- 2026-10-02: AI 공급망 보안을 미확인에서 이해 확인으로 갱신했다. 의존 라이브러리 롤백과 외부 통신·배포 변경·옵션 조사를 제안했다. 직전 설명의 대응 원칙을 활용한 답변으로 구현 경험이나 모든 공급망 구성요소의 독립 적용까지 확인한 것은 아니다.
- 2026-10-02: 상태 식별자 탈취와 접근 통제를 미확인에서 이해 확인으로 갱신했다. 요약 작업 소유자와 인증된 사용자 연결의 필요성을 이유와 함께 설명했다. 식별자를 사용자 ID 자체로 혼동했다고 단정하지 않는다.
- 2026-10-02: Confused Deputy를 미확인에서 부분 이해로 기록한 뒤 후속 답변으로 이해 확인으로 갱신했다. 신원 확인·로그인 외에 해당 요청의 노트 접근 권한 검사가 필요하다고 답했다. 학습자는 앞선 질문을 인증에 관한 것으로 해석해 인가를 생략했다고 설명했다. 이전 표현의 모호함은 개념 혼동의 확정 증거가 아니다.
- 2026-10-02: Tool Poisoning·Rug Pull을 미확인에서 이해 확인으로 갱신했다. 최초 승인 이후 안전성 보장의 오류와 도구 설명이 모델 판단에 미치는 영향을 직접 연결했다. 검사 빈도·방법을 구현한 증거는 아니다.
- 2026-10-02: Indirect Prompt Injection을 미확인에서 적용 확인으로 갱신했다. 리뷰 비교 사례에서 사용자 의도, 외부 지시, 모델의 자료 선택, 답변 왜곡을 연결하여 진단했다. 함께 설명한 Tool Poisoning은 답변 근거가 없어 미확인을 유지한다.
- 2026-10-02: 토큰 보관·만료·갱신을 미확인에서 부분 이해로 갱신했다. 새 토큰 발급만으로 유출 대응이 충분하지 않으며 기존 토큰의 무효화를 확인할 수 없다고 답했다. 후속 질문에서는 복사된 기존 토큰에 로그 삭제·새 토큰 발급이 영향을 주지 않을 것이라고 답했다. 교체·무효화의 구분은 확인했으나 보관 원칙 전반이나 독립 적용을 확인한 것은 아니다.
- 2026-10-02: Token Passthrough 설명 후 MCP 이용 자격 검사가 빠졌음을 정확히 답하고 외부 API 호출로는 이를 대체할 수 없다고 이유를 설명했다. 해당 개념과 토큰의 역할을 이해 확인으로 갱신했다. 동일한 경계 구분을 묻는 두 문항은 중복이었다.
- 2026-10-02: 다른 Server용 토큰 요청을 거부한다고 답했지만 이유를 실제 날씨 Server 요청으로 설명했다. 후속 답변에서 audience를 응답해야 할 대상이라고 이해했음이 확인돼 토큰 사용 대상과 요청 라우팅을 구분하도록 재설명한다.
- 2026-10-02: 최소 권한 질문에서 대상의 뜻을 물어 파일·폴더 등 리소스로 보충했다. 이후 수업 노트만 대상으로 잡았지만 대화창 요약에 생성·수정 권한도 부여해 부분 이해로 평가했다. 추가 요약 저장 기능 자체가 틀린 것은 아니며 주어진 기능과 추가 기능의 권한 요구를 구분하도록 보충한다.
- 2026-10-02: 재설명 후 원본 노트는 읽기만, 별도 요약 저장소는 생성·수정에 필요한 읽기·쓰기를 부여하고 이유를 설명하여 최소 권한을 이해 확인으로 갱신했다. 경로 철자 summaaries는 사례의 summaries로 해석했다.
- 2026-10-02: 노트 조회 과부하를 권한·입력 검사만으로 해결할 수 없다고 판단했으나 대응 방법은 제시하지 못해 요청 제한을 부분 이해로 평가했다.
