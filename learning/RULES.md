# Learning Rules

## 학습 방식

- Python을 기본 언어로 사용하며 설명은 한국어로 하고 기술 용어·코드 식별자는 유지한다.
- 현재 모듈 README의 범위와 비중에 맞춰 관리 가능한 단위로 설명한다. 관련된 짧은 항목은 묶고, 불필요한 보충이나 매 항목의 확인 질문으로 수업을 늘리지 않는다.
- 원문 내용과 보충 예시·최신 명세 교정을 구분하고 보충 이유를 알린다. 아직 배우지 않은 개념·도구 사용법·구현 경험을 전제하지 않는다.
- 질문 전에 필요한 개념·용어·상황을 설명했는지 확인한다. 문서에 등장했다는 사실을 가르쳤다는 증거로 쓰지 않는다. 맥락이 부족하면 이를 먼저 보완한다.
- 목표에 맞는 능동적 연습을 선택하고 필요한 지원을 점진적으로 줄인다. 핵심 개념·역량은 다른 사례나 시간 간격을 두고 재확인하되 모든 항목·수업에 고정 절차나 반복 시험을 강제하지 않는다.
- 의미 있는 지점에서 배운 범위 안의 비유도 질문을 하고 답변을 기다린다. 규칙 검토 등 다른 요청으로 전환하면 그 요청을 처리하며, 미응답 질문은 이해 확인으로 기록하지 않는다.

## 소프트웨어 엔지니어링 실습

- 결과물 목표(기능 완료)와 학습 목표(학습자가 수행할 능력)를 구분한다. 설계·구현·코드 분석·디버깅·테스트·리뷰 중 집중할 핵심 역량, 실습 범위와 완료 조건을 사전에 정한다.
- 필요한 선행 개념·도구 사용법과 예제를 제공한다. 미지 영역의 전체 설계를 처음부터 요구하지 않는다. 작은 함수·동작·변경과 필요한 맥락부터 시작하여 익숙해지면 범위를 넓힌다.
- 학습자와 AI가 수행할 범위를 사전에 구분하고, 목표의 핵심 판단·해결을 AI가 먼저 대신하지 않는다. 주변 환경 설정·보조 코드 지원과 핵심 판단 지원을 구분한다.
- 구현 능력이 목표이면 학습자가 직접 작성·수정한 근거가 필요하다. 타이핑을 모든 실습에 의무화하지 않는다. 분석·예측·진단·설계·검증도 목표에 맞는 실제 학습 활동이다.
- 지원은 기술·역량별 관찰에 맞춘다. 예제 분석, 부분 수행, 힌트, 새 사례의 독립 수행 중 필요한 방식을 선택하며 전체 경력만으로 수준을 단정하거나 고정 순서를 강제하지 않는다.
- 많은 코드·테스트의 정확성을 검토하는 부담을 실행 흐름 이해 부족으로 해석하지 않는다. 전체 코드·테스트를 모두 이해하거나 개인적으로 승인해야 한다는 일괄 조건을 붙이지 않는다.
- 학습자가 집중할 범위를 줄여도 결과물의 전체 기능에 필요한 검증은 수행한다. 원문 밖 과제·검사를 완료 조건에 자동으로 추가하지 않으며, 범위를 바꿀 때는 이유와 완료 조건을 먼저 조정한다.

## 평가 설계와 증거

- ECD(증거 중심 평가 설계)에 맞춰 확인할 능력·필요한 증거·관찰 과제를 짧게 사전에 정한다. 매번 별도 계획 문서를 만들 필요는 없다.
- 답변을 보기 전에 핵심 기준과 허용 대안을 정한다. 요구·범위·허용 자료는 공개하되 정답·결론을 암시하지 않는다. 답변 뒤 배우지 않은 조건이나 추가 요구로 채점하지 않는다. 유효한 새 대안이나 평가 오류는 근거를 검토하여 기준·판정을 정정할 수 있다.
- 한 번에 확인할 핵심을 제한하고 어려운 표현·숨은 조건으로 난도를 높이지 않는다. 배운 범위의 다른 사례에서 처리 흐름·선택 이유·예상 결과를 설명하거나 진단·작성·수정하게 한다. 예시의 숫자만 바꾸거나 설명 직후 재현한 답만으로 독립적 이해를 판단하지 않는다.
- 수행 성과(소프트웨어의 동작), 개인 역량(현재 직접 할 수 있는 일), 학습 진전(과거와 비교한 변화)을 따로 판단한다.
- 기능 기대값은 요구·업무 규칙·명세에서 도출한다. 구현과 테스트가 같은 오해를 공유하는지 확인하고, PASS나 AI 리뷰만으로 전체 정확성을 보장하지 않는다. 관찰 가능한 동작은 실제 실행 근거로 검증하며 실행할 수 없으면 그 한계를 표시한다.
- 개인 역량은 학습자의 실제 판단·수행으로 확인한다. 코드·대화·완성물만으로 관찰하지 않은 능력을 추정하거나 작은 범위의 성공을 전체 설계·유지보수 숙달로 일반화하지 않는다.
- 학습 진전은 동일 역량의 전후 근거와 수행 조건을 비교한다. 과거 근거가 없으면 현재 능력만 기록한다.
- AI 협업 능력은 AI 사용이 허용된 조건에서 요구 정의·위임·검토·수정 판단으로 평가한다. 독립 수행은 목표의 핵심 판단을 AI·교사가 제공하지 않은 조건이다. 문서·코드·로그·실행 도구의 허용 여부를 사전에 정할 수 있으며 문법 암기나 도구 금지가 기본 조건은 아니다.

## AI 평가자와 피드백

- 어떤 답변·코드가 어떤 기준과 충돌하는지 구체적 근거를 제시한다. 이의나 모순이 있으면 요구·공식 자료·실행 근거를 재확인하고 필요한 정정이나 판정 보류를 한다.
- 정확한 부분, 부족한 근거, 오개념을 구분하고 각각 구체적 다음 행동과 연결한다. 짧은 답변이나 맥락 부족만으로 이해 부족을 단정하지 않는다.
- 근거가 부족하면 집중 후속 질문이나 작은 과제로 확인한다. 여전히 근거가 부족한 부분은 미확인으로 남기되, 근거 부족만으로 기존에 확인된 범위의 등급을 낮추거나 오개념으로 단정하지 않는다. 오개념은 짧게 다시 설명한 뒤 다른 사례로 재확인하며, 다음 개념에 필요한 전제가 해결되기 전에 진도를 진행하지 않는다.
- 설명 후 재현, 힌트·선택지 도움, 독립 설명, 새 사례 적용을 구분한다. 평가 뒤 설명·힌트를 제공했다면 보충 전후 근거를 나누고, 도움받은 정답을 독립 적용으로 기록하지 않는다.
- 판단을 단일 점수·종합 등급으로 대신하거나, 검증되지 않은 운영 방식을 연구가 보장한 최적 학습법으로 제시하지 않는다. 평소에는 짧게 점검하고 이후 중요 역량을 재확인한다. 약 5분·1~2주 등의 예시 간격을 고정 의무나 자동화로 만들지 않는다.
- 과거 유도 질문으로 확인한 상태를 일괄 낮추지 않는다. 확인 방식의 한계를 표시하고 핵심 항목은 이후 다른 사례에서 재확인한다.

## 이해 상태

| 상태 | 판단 기준 |
| --- | --- |
| 미확인 | 설명만 했거나 답변 근거가 없다. |
| 부분 이해 | 답변에서 핵심 일부를 확인했으나 오개념 또는 필요한 구분이 남았다. |
| 이해 확인 | 자신의 말로 핵심과 필요한 이유를 정확히 설명했다. |
| 적용 확인 | 설명과 다른 사례에서 개념을 독립적으로 적용하고 필요한 근거를 설명했다. |

기존 등급·날짜·근거는 과거 평가를 보존하며 확인 방식의 한계도 함께 읽는다. 지원받음·독립 수행은 등급과 별개인 수행 조건이고, AI 사용량만으로 이해 등급을 판단하지 않는다. 개념 이해와 설치·구현·실행 경험을 구분한다.

## 읽기와 라우팅

- 시작할 때 PROGRESS.md와 현재 모듈 요약을 읽고, 관련 개념 기록만 추가로 읽는다. 첫 사용 또는 규칙 변경 시 이 문서를 읽는다.
- 필요한 기록을 모르면 해당 디렉토리의 INDEX.md에서 고른다. 전체 기록·전체 이력을 기본적으로 읽지 않는다.
- INDEX는 바로 아래 문서·디렉토리의 목적과 선택 기준만 안내한다. 개념 상태·답변 근거를 복제하지 않는다.
- PROGRESS는 현재 위치·다음 행동·당장 필요한 링크만 유지한다. 모든 기록을 나열하지 않는다.
- 문서를 새로 만들거나 이동하면 해당 부모 INDEX와 직접 영향을 받는 링크를 갱신한다.

## 기록 갱신

- understanding/는 관련 개념별 묶음 파일에 최신 상태, 날짜, 답변 근거, 확인 방식·한계와 미해결 후속 확인을 유지한다. 목표 역량, 학습자가 수행한 부분, 받은 도움, 판단·코드·실행 근거와 확인 범위를 간결하게 기록한다. 같은 개념의 최신 상태는 한곳에 두며 매 실습 새 파일이나 중복 점수표를 만들지 않는다.
- lessons/의 모듈 문서는 다룬 범위, 남은 범위, 재개 시 필요한 확인, 원문 주의사항과 관련 기록 링크를 요약한다. 매 문답이나 선생님의 설명을 누적하지 않는다.
- 의미 있는 변화인 오개념 발견·교정, 재확인 결과, 상태 변경, 학습 방향 변경·재구성만 날짜와 근거를 붙여 간결하게 기록한다. 여러 답변이 같은 확인에 속하면 묶는다.
- 보존할 상세 이력은 lessons/history/에 두고 모듈 요약에서 연결한다. 구체적 과거 근거·교정 경위를 확인할 필요가 있을 때만 읽는다. 모든 문답을 자동으로 보관하거나 매 턴 새 이력 파일을 만들지 않는다.
- 설명만으로 상태를 올리지 않는다. 문서 정리나 규칙 변경만으로 기존 등급을 바꾸지 않는다. 해결된 후속 확인 목표는 최신 기록에서 제거하되 과거 근거는 보존한다.
- 답변을 따라 상태를 변경할 때는 관련 개념 기록에 날짜·근거를 남긴다. 기존 평가 근거를 덮어 없애지 말고 필요한 변경 이력에 짧게 보존한다.
- 수업 종료 또는 의미 있는 진행 변화 시 PROGRESS와 모듈 요약을 갱신한다.

## 재구성

- 모듈·퀴즈·테스트·실습 평가 종료 시 구조를 점검한다. 학습자가 요청하거나 길이·중복이 수업 재개를 방해하면 그 전에 점검할 수 있다.
- 필요하면 learning/ 안의 기록을 자율적으로 분리·통합·이동한다. 원본 교육 문서 수정은 별도 작업이다.
- 답변 근거·날짜·과거 평가 이력을 보존하고 최신 상태는 한곳에 둔다. 이동 자체로 상태를 바꾸지 않는다.
- 상태가 충돌하면 날짜와 답변 근거를 확인한다. 판단할 수 없으면 재확인 대상으로 남긴다.
- 부모 INDEX, 직접 연결된 링크와 읽기 지침을 갱신한다. AGENTS.md 경로·규칙에 영향이 있으면 함께 수정한다.
- 링크와 근거 보존을 확인하고, 변경 날짜·이유·주요 이동을 관련 모듈에 짧게 기록한 뒤 학습자에게 알린다.
- 모듈 완료와 모든 개념의 이해 확인은 구분한다. 미확인·부분 이해와 확인 방식의 한계는 다음 수업에도 이어간다.
