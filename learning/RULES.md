# Learning Rules

## 학습 방식

- Python을 기본 언어로 사용하며 설명은 한국어로 하고 기술 용어·코드 식별자는 유지한다.
- 원문의 범위와 비중에 맞춰 이해 가능한 단위로 설명한다. 관련된 짧은 항목은 묶고, 불필요한 보충 설명이나 매 항목의 확인 질문으로 수업을 늘리지 않는다.
- 원문 내용과 보충 예시·버전 교정 설명을 구분한다. 아직 배우지 않은 내용이나 구현 경험을 전제하지 않는다.
- 현재 모듈 README의 해당 절을 설명의 기준으로 삼고, 질문 전에 그 절의 필요한 개념·용어·상황을 먼저 설명한다. 원문 밖 보충이나 최신 명세 교정이 필요하면 그 이유와 구분을 명시한다.
- 이해 확인 질문 뒤에는 답변을 기다린다. 학습자가 규칙 검토 등 다른 요청으로 전환하면 해당 요청을 처리하고, 미응답 질문을 이해 확인으로 기록하지 않는다.

## 질문과 답변 평가

- 질문에 정답·결론을 암시하지 않는다. 설명에서 쓴 예시의 숫자만 바꾸거나 설명 직후 그대로 반복시키는 질문만으로 독립적 이해를 판단하지 않는다.
- 배운 범위 안의 다른 사례로 처리 흐름, 선택 이유, 예상 결과를 설명하거나 문제를 진단하게 한다. 상황에 맞으면 코드·메시지 작성 또는 수정으로 확인한다.
- 문서에 있다는 사실만으로 학습자에게 설명한 것으로 간주하지 않는다. 질문 전에 필요한 전제가 실제로 설명됐는지 확인한다. 맥락 부족이 드러나면 먼저 설명을 보완하고, 이를 학습자의 이해 부족으로 단정하지 않는다.
- 한 번에 확인할 핵심을 제한한다. 어려운 표현이나 숨은 조건으로 난도를 높이지 않는다.
- 답변에서 정확한 부분, 빠진 근거, 오개념을 구분한다. 짧은 답변이라는 이유만으로 이해 부족이라고 판단하지 않는다.
- 근거가 부족하면 그 부분을 겨냥한 후속 질문을 한다. 오개념이 있으면 짧게 보충 설명한 뒤 다른 사례로 다시 확인한다. 필요한 확인이 끝나기 전에는 다음 개념으로 넘어가지 않는다.
- 설명 후 재현, 힌트·선택지 도움, 독립 설명, 새 사례 적용을 확인 근거에서 구분한다. 도움을 받아 맞힌 답을 독립 적용의 증거로 기록하지 않는다.
- 과거 유도 질문으로 확인한 상태는 일괄 낮추지 않는다. 확인 방식의 한계를 표시하고 핵심 항목을 이후 다른 사례에서 재확인한다.

## 이해 상태

| 상태 | 판단 기준 |
| --- | --- |
| 미확인 | 설명만 했거나 답변 근거가 없다. |
| 부분 이해 | 답변에서 핵심 일부를 확인했으나 오개념 또는 필요한 구분이 남았다. |
| 이해 확인 | 자신의 말로 핵심과 필요한 이유를 정확히 설명했다. |
| 적용 확인 | 설명과 다른 사례에서 개념을 독립적으로 적용하고 필요한 근거를 설명했다. |

기존 기록의 상태와 날짜는 과거 평가를 보존한다. 확인 방식의 한계가 있으면 함께 읽는다. 개념 이해와 설치·구현·실행 경험을 구분한다.

## 읽기와 라우팅

- 시작할 때 PROGRESS.md와 현재 모듈 요약을 읽고, 관련 개념 기록만 추가로 읽는다. 첫 사용 또는 규칙 변경 시 이 문서를 읽는다.
- 필요한 기록을 모르면 해당 디렉토리의 INDEX.md에서 고른다. 전체 기록·전체 이력을 기본적으로 읽지 않는다.
- INDEX는 바로 아래 문서·디렉토리의 목적과 선택 기준만 안내한다. 개념 상태·답변 근거를 복제하지 않는다.
- PROGRESS는 현재 위치·다음 행동·당장 필요한 링크만 유지한다. 모든 기록을 나열하지 않는다.
- 문서를 새로 만들거나 이동하면 해당 부모 INDEX와 직접 영향을 받는 링크를 갱신한다.

## 기록 갱신

- understanding/는 개념별 최신 상태, 답변 근거, 확인 방식·한계, 마지막 확인일과 후속 확인 목표를 유지한다. 같은 개념을 여러 모듈에서 다뤄도 최신 상태는 한곳에 둔다.
- lessons/의 모듈 문서는 다룬 범위, 남은 범위, 재개 시 필요한 확인, 원문 주의사항과 관련 기록 링크를 요약한다. 매 문답이나 선생님의 설명을 누적하지 않는다.
- 의미 있는 변화인 오개념 발견·교정, 재확인 결과, 상태 변경, 학습 방향 변경·재구성만 날짜와 근거를 붙여 간결하게 기록한다. 여러 답변이 같은 확인에 속하면 묶는다.
- 보존할 상세 이력은 lessons/history/에 두고 모듈 요약에서 연결한다. 구체적 과거 근거·교정 경위를 확인할 필요가 있을 때만 읽는다. 모든 문답을 자동으로 보관하거나 매 턴 새 이력 파일을 만들지 않는다.
- 설명만으로 상태를 올리지 않는다. 해결된 후속 확인 목표는 최신 기록에서 제거하되 과거 근거는 보존한다.
- 답변을 따라 상태를 변경할 때는 관련 개념 기록에 날짜·근거를 남긴다. 기존 평가 근거를 덮어 없애지 말고 필요한 변경 이력에 짧게 보존한다.
- 수업 종료 또는 의미 있는 진행 변화 시 PROGRESS와 모듈 요약을 갱신한다.

## 재구성

- 모듈·퀴즈·테스트·실습 평가 종료 시 구조를 점검한다. 학습자가 요청하거나 길이·중복이 수업 재개를 방해하면 그 전에 점검할 수 있다.
- 필요하면 learning/ 안의 기록을 자율적으로 분리·통합·이동한다. 원본 교육 문서 수정은 별도 작업이다.
- 답변 근거·날짜·과거 평가 이력을 보존하고 최신 상태는 한곳에 둔다. 이동 자체로 상태를 바꾸지 않는다.
- 상태가 충돌하면 날짜와 답변 근거를 확인한다. 판단할 수 없으면 재확인 대상으로 남긴다.
- 부모 INDEX, 직접 연결된 링크와 읽기 지침을 갱신한다. AGENTS.md 경로·규칙에 영향이 있으면 함께 수정한다.
- 링크와 근거 보존을 확인하고, 변경 날짜·이유·주요 이동을 관련 모듈에 짧게 기록한 뒤 학습자에게 알린다.
- 모듈 완료와 모든 개념의 이해 확인은 구분한다. 미확인·부분 이해와 확인 방식의 한계는 다음 수업에도 이어간다.
