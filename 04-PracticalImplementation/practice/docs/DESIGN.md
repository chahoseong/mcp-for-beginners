# 과제 1: 상품 견적 MCP 작업 흐름 설계

## 확정된 방향

- 주제: 고객의 예산과 요청 수량에 맞는 상품 견적 초안 작성
- 데이터 출처: [DummyJSON 상품 데이터](https://dummyjson.com/docs/products)
- 데이터 성격: 테스트용 상품 정보이며 실제 판매 가격과 재고를 의미하지 않음
- 현재 과제 범위: 문제 정의, Tool 3~4개, Resource 1개, Prompt 1개, 전체 작업 흐름과 실패 처리 설계
- 기준 모듈: [Practical Implementation](../../README.md)

## 1. 해결할 문제

영업 담당자의 조건 검색과 견적 초안 작성 작업을 설계한다.

- 사용자와 사용 상황: 영업 담당자가 고객의 구매 요구를 받아 고객에게 보낼 상품 견적 초안을 준비한다.
- 요청 방식: 특정 상품을 지정하지 않고, 구매 조건에 맞는 상품을 검색한다.
- 예산 기준: 배송비와 적용되는 세금을 포함한 최종 금액
- 사용자가 요청할 문장: 아래 설계 기준 예시 사용
- 성공했을 때 제공할 결과: 아래 설계 기준 예시 사용
- 견적 정책: 아래 Resource의 통화, 할인, 배송비, 세금, 반올림, 안내기간 규칙을 적용한다.

### 설계 기준 예시

상품 종류, 수량, 예산은 다음 예시를 기준으로 도구를 설계하며 다른 값도 입력받을 수 있도록 한다.

- 요청 문장: "배송비와 적용되는 세금을 포함해 총 2,000 USD 이내로 동일 모델의 스마트폰 3대를 구매할 수 있는 상품을 찾아 견적 초안을 만들어줘."
- 상품 범위: 한 모델의 상품 여러 개로 구성된 견적
- 성공 결과: 재고와 최종 예산 조건을 만족하는 모델별 견적 후보 목록. 각 후보에는 상품 ID와 이름, 수량, 단가, 할인 내역, 재고 확인 결과, 배송비, 세금, 최종 금액, 견적 조건을 포함한다.
- 예시 예산은 2,000 USD이다. USD는 DummyJSON 데이터에서 확인한 통화가 아니라 과제용 견적 정책으로 정한 통화이다.
- 후보 처리: 조건을 만족하는 후보들을 영업 담당자에게 보여준다. 시스템이 최종 상품을 자동 선택하지 않는다.
- 조건을 만족하는 후보가 없으면 견적 생성 성공으로 처리하지 않고, 제외 사유와 조정할 수 있는 조건을 안내한다.
- 이 과제에서 구매 가능 여부는 카테고리·검색어 일치, 요청 수량 이상의 재고, 최종 예산 충족으로 정의한다. 실제 공급업체의 최소 주문 수량, 배송 지역, 주문·예약·결제 처리는 범위에 포함하지 않는다.

### 데이터 사용

[DummyJSON 상품 문서](https://dummyjson.com/docs/products)의 조회 데이터를 다음처럼 도구의 필드로 연결한다. 상품 목록은 조회만 하며 DummyJSON의 상품 생성·수정·삭제 기능은 사용하지 않는다.

| 원본 필드                     | 설계에서 사용하는 값             |
| ----------------------------- | -------------------------------- |
| `id`                        | `product_id`                   |
| `title`                     | `name`                         |
| `category`, `description` | 카테고리 조회와 추가 검색어 필터 |
| `stock`                     | 현재 재고 확인                   |
| `price`                     | 할인 전`unit_price`            |
| `discountPercentage`        | `discount_percentage`          |

## 2. Tools

도구는 다음 3개로 역할을 나눈다.

| 이름                | 역할                                                            | 다음 단계에 전달할 핵심 결과                        |
| ------------------- | --------------------------------------------------------------- | --------------------------------------------------- |
| `search_products` | 상품 종류와 검색어에 맞는 후보 조회                             | 후보 상품 ID와 상품 정보                            |
| `check_stock`     | 상품 ID와 요청 수량으로 공급 가능 여부 확인                     | 상품 ID, 요청 수량, 현재 재고, 공급 가능 여부       |
| `calculate_quote` | 상품 ID와 수량을 받아 원본 가격·할인과 견적 정책으로 금액 계산 | 단가, 할인 내역, 상품 금액, 배송비, 세금, 최종 금액 |

- 예산 충족 여부는 할인·배송비·세금 계산을 마친 최종 금액으로 판단한다.
- `check_stock`은 현재 재고를 조회하며 재고를 예약하지 않는다.
- `calculate_quote`의 가격·할인·정책은 서버가 출처에서 확인한 값을 사용한다.
- 견적 초안의 문장과 표 구성은 Host/모델이 Prompt를 활용해 수행하는 방향으로 설계한다.

### 공통 출력 규칙

- 반환 자료형은 `object`이며 성공 시 `status: "ok"`와 아래 도구별 필드를 포함한다.
- 작업을 수행할 수 없으면 `status: "error"`, `error: {code: string, message: string, retryable: boolean}`을 반환한다.
- 이는 도구가 제공하는 애플리케이션 데이터의 설계이며 MCP 메시지 전체의 형식은 아니다.
- 빈 검색 결과, 재고 부족, 예산 초과는 정상적으로 확인한 결과로 표현한다. 데이터 조회나 계산 자체의 실패와 구분한다.
- 상품 ID는 양의 정수, 수량은 1 이상의 정수, 예산은 0보다 큰 유한한 USD 금액이어야 한다. 금액 입력은 소수 둘째 자리까지 허용한다.

| 오류 코드                | 의미                                         | 재시도 가능 여부       |
| ------------------------ | -------------------------------------------- | ---------------------- |
| `INVALID_INPUT`        | 인자 형식·범위 또는 카테고리가 잘못됨       | 아니오. 입력 수정 필요 |
| `PRODUCT_NOT_FOUND`    | 상품 ID로 상품을 찾을 수 없음                | 아니오                 |
| `UPSTREAM_TIMEOUT`     | 외부 API 응답 시간 초과                      | 예                     |
| `UPSTREAM_UNAVAILABLE` | 일시적 접속 실패, HTTP 429 또는 5xx          | 예                     |
| `INVALID_RESPONSE`     | 필요한 데이터 필드 누락 또는 형식·범위 오류 | 아니오                 |
| `POLICY_UNAVAILABLE`   | 서버의 견적 정책 누락 또는 오류              | 아니오                 |

모든 외부 API 요청은 10초 후 시간 초과로 처리한다. 재시도 가능한 오류에 한해 1회 재시도하며, 하나의 요청은 최대 2회 시도한다. HTTP 429의 재시도 대기시간이 30초를 초과하면 현재 작업에서는 재시도하지 않고 실패를 보고한다.

### `search_products`

| 항목      | 설계                                                                                                                                      |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 역할      | 상품 카테고리와 선택적 검색어에 맞는 후보를 조회한다.                                                                                     |
| 입력      | `category: string` 필수, `keyword: string` 선택                                                                                       |
| 출력      | `products: array<object>` — 각 항목의 `product_id: integer`, `name: string`, `category: string`; `count: integer` — 후보 개수 |
| 실패 조건 | 유효하지 않은 카테고리 또는 인자, 외부 API 접속 실패·시간 초과, 응답 형식 오류                                                           |

- 카테고리는 DummyJSON의 카테고리 식별자를 사용한다. 검색어가 있으면 해당 카테고리 안에서 이름과 설명을 검색하는 서버의 검색 규칙을 적용한다.
- 선택적 검색어의 기본값은 빈 문자열이며 추가 필터를 적용하지 않는다. 검색어는 앞뒤 공백을 제거하고, 대소문자를 구분하지 않는 문자열 포함 조건으로 처리한다.
- 외부 API가 결과를 페이지로 나누면 서버가 필요한 페이지를 모두 조회한다. 일부 페이지만 조회한 목록을 전체 결과로 표시하지 않는다.
- 검색 결과가 없으면 `status: "ok"`, `products: []`, `count: 0`을 반환한다.
- 검색 단계에서는 예산 충족 여부를 확정하지 않는다.

### `check_stock`

| 항목      | 설계                                                                                                                                                                                  |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 역할      | 후보 상품의 현재 재고가 요청 수량 이상인지 확인한다.                                                                                                                                  |
| 입력      | `product_id: integer` 필수, `quantity: integer` 필수·1 이상                                                                                                                      |
| 출력      | `product_id: integer`, `requested_quantity: integer`, `stock: integer`, `in_stock: boolean` — 재고가 요청 수량 이상인지, `checked_at: string` — 시간대가 포함된 확인 시각 |
| 실패 조건 | 잘못된 상품 ID·수량, 상품을 찾을 수 없음, 외부 API 접속 실패·시간 초과, 재고 필드 누락·형식 오류                                                                                   |

- 재고 부족이면 `status: "ok"`, `in_stock: false`를 반환한다.
- 조회 시점의 재고 정보이며 재고 예약이나 주문을 수행하지 않는다.
- `stock`은 0 이상의 정수여야 한다. 조회 시각은 현재 작업에서 확인한 정보임을 표시하는 데 사용한다.

### `calculate_quote`

| 항목      | 설계                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 역할      | 서버가 조회한 상품 가격·할인과 견적 정책을 사용해 후보의 최종 금액을 계산하고 예산과 비교한다.                                                                                                                                                                                                                                                                                                                               |
| 입력      | `product_id: integer` 필수, `quantity: integer` 필수·1 이상, `budget: number` 필수·0 초과                                                                                                                                                                                                                                                                                                                             |
| 출력      | `product_id: integer`, `name: string`, `quantity: integer`, `currency: string`, `unit_price: number`, `discount_percentage: number`, `discount_amount: number`, `subtotal: number` — 할인 후 상품 금액, `shipping_fee: number`, `tax: number`, `total: number`, `within_budget: boolean` — 최종 금액이 예산 이하인지, `policy_version: string`, `generated_at: string`, `valid_until: string` |
| 실패 조건 | 잘못된 입력, 상품을 찾을 수 없음, 외부 API 접속 실패·시간 초과, 가격·할인 필드 오류, 견적 정책 누락·오류                                                                                                                                                                                                                                                                                                                   |

- 모델이 단가나 할인율을 임의로 입력하지 않는다. 서버가 상품 ID로 확인한 데이터와 서버가 관리하는 정책을 사용한다.
- 예산을 초과해도 계산 자체가 성공했다면 `status: "ok"`, `within_budget: false`와 계산 내역을 반환한다.
- 통화, 배송비, 세율, 계산 순서, 반올림, 유효기간은 아래 Resource와 같은 서버 정책을 사용한다.
- 단가는 0 이상의 유한한 수치, 할인율은 0~100 범위의 유한한 수치여야 한다. 필드가 없거나 범위가 잘못되면 추측하지 않고 `INVALID_RESPONSE`를 반환한다.
- Python 구현 시 내부 금액 계산에는 `Decimal`을 사용하고 `ROUND_HALF_UP`으로 반올림한다. JSON 출력은 소수 둘째 자리까지의 금액을 `number`로 반환한다.

## 3. Resource와 Prompt

### Resource: 견적 정책

- URI: `quote://policy`
- 제공할 내용: 통화, 배송비, 할인·세금 계산 규칙, 반올림, 견적 안내기간, 정책 버전
- 사용 시점: Host가 요청 처리 시작 시 읽어 요구 조건과 정책을 확인하고, 견적 후보를 제시할 때 적용한 정책을 설명한다.
- 서버의 `calculate_quote`는 이 Resource가 설명하는 동일한 정책 원본을 사용한다. 모델이 읽은 정책 수치를 도구 인자로 다시 넘기거나, 모델이 임의로 정책을 수정하지 않는다.
- 제공 형식: `text/markdown`. Host가 내용을 읽어 모델 문맥에 포함한다.

아래 정책은 승인된 과제용 가정이며 실제 상거래·세법을 나타내지 않는다.

| 정책          | 규칙                                                                                                                                   |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 통화          | USD. DummyJSON의 가격 숫자를 USD로 해석하는 과제용 규칙이며 환율 변환은 하지 않는다.                                                   |
| 배송비        | 후보 견적당 20.00 USD. 요청 수량과 관계없이 한 번 부과한다. 후보별 견적은 서로 독립된 대안이므로 배송비를 후보 사이에 합산하지 않는다. |
| 할인          | 해당 상품의`discountPercentage`를 상품 금액에 한 번 적용한다.                                                                        |
| 세금          | 할인 후 상품 금액의 10%. 배송비에는 세금을 적용하지 않는다.                                                                            |
| 반올림        | 계산 단계에서 금액을 소수 둘째 자리까지 사사오입한다. 정확한 순서는 아래와 같다.                                                       |
| 견적 안내기간 | 생성 시각부터 7일. 가격·재고를 예약하거나 보장하지 않으며 실제 주문 단계에서는 재확인한다.                                            |
| 정책 버전     | `v1`                                                                                                                                 |

계산 순서:

1. 할인 전 상품 금액 = 단가 × 수량을 소수 둘째 자리로 반올림
2. 할인 금액 = 할인 전 상품 금액 × 할인율 / 100을 소수 둘째 자리로 반올림
3. 할인 후 상품 금액(`subtotal`) = 할인 전 상품 금액 − 할인 금액
4. 세금(`tax`) = 할인 후 상품 금액 × 0.10을 소수 둘째 자리로 반올림
5. 최종 금액(`total`) = 할인 후 상품 금액 + 20.00 + 세금
6. 예산 충족(`within_budget`) = 최종 금액이 입력 예산 이하인지

`calculate_quote` 출력의 `policy_version`은 적용한 정책 버전이다. `generated_at`은 계산 완료 시각, `valid_until`은 그 시각부터 7일 뒤의 시각이다. 시간 필드는 시간대가 포함된 ISO 8601 형식으로 반환한다.

### Prompt: 견적 후보 준비

- 이름: `prepare_quote`
- 목적: 영업 담당자의 조건을 일관된 작업 지시로 변환하고, 후보 확인·견적 계산·실패 보고·비교표 작성 절차를 안내한다.
- 사용 시점: 영업 담당자가 Host에서 이 Prompt를 선택하고 조건을 입력해 견적 작업을 시작할 때
- 반환 메시지: 아래 템플릿을 채운 `role: "user"`의 텍스트 메시지 1개
- Prompt는 템플릿을 제공하며 도구를 직접 호출하거나 견적을 계산하지 않는다.

입력 인자:

| 인자         | 자료형     | 필수 여부 | 의미·예시                                  |
| ------------ | ---------- | --------- | ------------------------------------------- |
| `category` | `string` | 필수      | 상품 카테고리 식별자. 예:`smartphones`    |
| `quantity` | `string` | 필수      | 수량을 표현한 문자열. 예:`"3"`            |
| `budget`   | `string` | 필수      | USD 예산을 표현한 문자열. 예:`"2000.00"`  |
| `keyword`  | `string` | 선택      | 카테고리 내 추가 검색어. 기본값은 빈 문자열 |

Prompt 인자는 문자열로 전달한다. `quantity`와 `budget`은 형식·범위를 검증한 뒤, Tool 호출에서는 각각 `integer`와 `number`로 전달한다. 누락되거나 잘못된 입력이 있으면 먼저 수정을 요청한다. 문자열 인자와 사용자 선택 방식은 [MCP Python SDK의 Prompt 설명](https://py.sdk.modelcontextprotocol.io/servers/prompts/)을 참고했다.

메시지 템플릿:

```text
영업 담당자가 고객에게 보낼 상품 견적 후보를 준비해주세요.

구매 조건:
- 상품 카테고리: {category}
- 추가 검색어: {keyword} (비어 있으면 추가 조건 없음)
- 동일 모델의 요청 수량: {quantity}개
- 배송비와 세금까지 포함한 총 예산: {budget} USD

Host가 제공한 quote://policy를 확인하고 해당 정책을 적용해주세요.
정책을 읽지 못했다면 금액을 추측하지 말고 작업을 중단해주세요.

1. search_products로 카테고리와 검색어에 맞는 후보를 조회해주세요.
2. 각 후보의 product_id와 요청 수량으로 check_stock을 호출해주세요.
3. 재고가 충분한 후보마다 calculate_quote를 호출해주세요.
   product_id, quantity, budget을 전달하며 가격·할인율은 직접 입력하지 마세요.
4. 재고가 충분하고 within_budget이 true인 후보들을 모두 보여주세요.
   한 후보는 하나의 모델을 요청 수량만큼 구매하는 독립된 견적입니다.
   서로 다른 후보의 금액이나 배송비를 합산하지 마세요.
5. 상품 ID, 상품명, 수량, 단가, 할인 금액, 할인 후 상품 금액,
   배송비, 세금, 최종 금액, 재고 확인 시각, 견적 안내기간을 비교표로 작성해주세요.
   적용한 정책 버전과 가격·재고를 예약하지 않았다는 점도 표시해주세요.
6. 재고 부족·예산 초과로 제외된 후보와 조회에 실패한 후보를 구분해 안내해주세요.
   조건을 만족하는 후보가 없다면 그 이유를 설명하고 조건 변경을 요청해주세요.
   조회 실패가 남아 있다면 전체 후보 검증을 완료했다고 표현하지 마세요.

최종 상품은 영업 담당자가 선택합니다. 상품을 자동 선택하거나 주문하지 마세요.
```

## 4. 전체 작업 흐름

Host와 모델이 아래 순서로 작업을 진행한다. MCP 서버는 Resource·Prompt·Tool을 제공하고, 여러 Tool을 호출하는 전체 작업의 진행은 Host와 모델이 담당한다.

1. **요청 준비와 Prompt 사용**
   - 영업 담당자가 `prepare_quote`를 선택하고 카테고리, 수량, 예산, 선택적 검색어를 입력한다.
   - Host/Client가 Prompt의 메시지 템플릿을 받아 모델 문맥에 포함한다.
   - 누락·잘못된 수량·예산이 있으면 먼저 수정하도록 안내하며 Tool을 호출하지 않는다.
2. **Resource 읽기**
   - Host/Client가 `quote://policy`를 읽어 모델 문맥에 포함한다.
   - USD 정책과 요청 예산의 통화를 확인한다. 다른 통화를 요청하면 USD 예산으로 다시 입력하도록 안내한다.
   - 정책을 읽지 못하면 종료한다. 모델이 배송비나 세율을 추측하지 않는다.
3. **상품 후보 검색**
   - `search_products(category, keyword)`를 호출한다.
   - `products`의 각 `product_id`를 다음 단계의 입력으로 사용한다.
   - 빈 목록이면 검색 조건에 맞는 상품이 없음을 알리고 카테고리·검색어 변경을 요청한다.
4. **후보별 재고 확인**
   - 각 `product_id`와 원래 요청의 `quantity`로 `check_stock(product_id, quantity)`를 호출한다.
   - `in_stock: false`이면 재고 부족으로 제외한다.
   - 성공한 결과의 `product_id`, `requested_quantity`, `checked_at`을 유지한다.
5. **재고가 충분한 후보별 견적 계산**
   - 재고 결과의 `product_id`, `requested_quantity`와 원래 요청의 `budget`을 `calculate_quote`에 전달한다.
   - `within_budget: false`이면 예산 초과로 제외하고 `total`과 초과 금액을 안내용으로 유지한다.
   - Resource와 계산 결과의 `policy_version`이 다르면 견적을 제시하지 않고 작업을 중단한다. 정책을 다시 확인한 새 작업으로 진행한다.
6. **후보 비교표와 견적 초안 제공**
   - 재고와 예산을 충족한 결과를 `product_id`로 연결해 비교표를 만든다.
   - 최종 금액 오름차순, 동률이면 상품 ID 오름차순으로 표시한다. 정렬은 표시 순서이며 상품 선택이 아니다.
   - Prompt의 출력 안내에 따라 금액 내역, 적용 정책, 확인 시각과 안내기간을 포함한다.
   - 전체 검색 후보 수, 재고 부족 수, 예산 초과 수, 검증 완료 수, 조회 실패 수를 함께 안내한다.
   - 성공 결과에는 조건을 만족하는 후보 목록을 제공하며 영업 담당자가 최종 상품을 선택한다.

### 단계 간 데이터 연결 예시

| 출처                                             | 다음 단계에 전달하는 값                                      |
| ------------------------------------------------ | ------------------------------------------------------------ |
| Prompt 입력`category`, `keyword`             | `search_products.category`, `search_products.keyword`    |
| Prompt 입력`quantity`                          | 정수로 검증해`check_stock.quantity`에 전달                 |
| 검색 결과`products[i].product_id`              | `check_stock.product_id`                                   |
| 재고 결과`product_id`, `requested_quantity`  | `calculate_quote.product_id`, `calculate_quote.quantity` |
| Prompt 입력`budget`                            | 숫자로 검증해`calculate_quote.budget`에 전달               |
| 견적 결과`within_budget`, `total`            | 후보 포함 여부와 표시 순서 판단                              |
| 재고 결과와 견적 결과의`product_id`            | 비교표에서 같은 상품의 정보 연결                             |
| Resource 정책 버전과 견적 결과`policy_version` | 동일 정책으로 계산했는지 확인                                |

### 중간 실패 처리

| 상황                                      | 처리                                                                                                                                   |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Prompt 선택·메시지 조회 실패             | 작업을 시작하지 않고 Host에 실패 원인을 표시한다. 누락된 인자가 있으면 다시 입력하도록 안내한다.                                       |
| Resource 조회 실패                        | 정책을 추측하지 않고 전체 작업을 중단한다.                                                                                             |
| 상품 검색 실패                            | 재시도 가능한 오류만 1회 재시도한다. 여전히 실패하면 전체 작업을 중단한다. 일부 페이지 조회 실패도 검색 실패로 처리한다.               |
| 특정 후보의 재고·견적 조회 실패          | 재시도 가능한 오류만 1회 재시도한다. 계속 실패하면 해당 후보는 미검증으로 남기고 다른 후보를 처리한다.                                 |
| 상품 ID가 더 이상 존재하지 않음           | 해당 후보를 제외하고 상품을 조회할 수 없었음을 알린다.                                                                                 |
| 재고 부족                                 | 해당 후보를 제외하고 요청 수량과 확인 재고를 안내한다.                                                                                 |
| 예산 초과                                 | 해당 후보를 제외하고 최종 금액과 초과 금액을 안내한다.                                                                                 |
| 견적 정책 오류 또는 버전 불일치           | 개별 상품 문제가 아닌 공통 계산 기준의 문제이므로 전체 작업을 중단한다.                                                                |
| 모든 후보를 확인했지만 적합한 후보가 없음 | 확인된 재고·예산 제외 사유를 안내하고 조건 변경을 요청한다. 임의로 예산이나 수량을 변경하지 않는다.                                   |
| 일부 후보가 미검증으로 남음               | 확인된 적합 후보는 제공하되 조회 실패 상품과 부분 완료 사실을 표시한다. 적합 후보가 없더라도 모든 상품이 부적합하다고 단정하지 않는다. |

전체 작업 결과는 모든 후보의 확인을 마치고 적합 후보가 있으면 **완료**, 일부 후보가 미검증이면 **부분 완료**, 모든 후보를 확인했지만 적합 후보가 없으면 **조건 불충족**, 필수 단계 또는 공통 정책 오류로 진행할 수 없으면 **실패**로 구분한다. Tool의 `status`는 개별 도구 실행 결과이므로 이 전체 작업 결과와 구분한다.

### 계산과 흐름 확인 예시

아래 값은 설계를 점검하기 위한 가상 데이터이며 실제 DummyJSON 상품의 값이 아니다. 요청 수량은 3개, 예산은 2,000 USD이다.

| 후보 | 단가    | 할인율 | 재고 | 확인 결과                                                                                         |
| ---- | ------- | ------ | ---- | ------------------------------------------------------------------------------------------------- |
| A    | 600 USD | 10%    | 5개  | 할인 전 1,800 − 할인 180 = 상품 금액 1,620; 세금 162 + 배송비 20으로 최종 1,802 USD. 후보에 포함 |
| B    | 650 USD | 0%     | 4개  | 상품 금액 1,950 + 세금 195 + 배송비 20 = 2,165 USD. 예산보다 165 USD 높아 제외                    |
| C    | 500 USD | 5%     | 2개  | 요청 수량 3개보다 재고가 적어 제외. 견적 계산을 호출하지 않음                                     |

후보 A의 최종 금액이 1,802 USD일 때 예산이 정확히 1,802 USD이면 포함하고, 1,801.99 USD이면 제외한다. 재고는 요청 수량과 같아도 충분한 것으로 판단한다. 조회에 실패한 별도 후보 D가 있다면 A의 견적은 보여주되 결과를 부분 완료로 표시한다.
